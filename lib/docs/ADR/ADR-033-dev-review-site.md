# ADR-033: 내부 개발·검수 사이트 — Go 서버, 편집 세션, 사람과 에이전트가 같은 편집 경로

## Context

- 지금 검수는 흩어져 있다. 작업실 검수 페이지(`studio/?page=review`, ADR-031), 픽스처(`tests/fixtures/runtime/*.html`), 시트 스크립트(`scripts/glyph_legibility_sheet.py` 등), 감사(`glyph_*_audit.py`), 검증 요약(`tmp/verify-summary.json`), 에이전트가 그때그때 만든 전후 시트(`tmp/…`)가 따로 논다. 2026-10-18에는 시트를 사람 기기(m4mbp16)로 손으로 복사해 보였다.
- 미리보기는 nginx(127.0.0.1·tailscale IP의 8470)가 작업 트리를 읽기 전용으로 보여 준다. HTTP라 보안 컨텍스트가 아니어서 작업실의 File System Access 저장이 내려받기로 떨어진다. 브라우저에서 고친 글꼴을 저장소 파일에 **반영할 길이 없다**.
- 작업실에는 이미 사람의 조작과 같은 경로를 타는 자동화 창구 `window.FontStudio`가 있다(`select`·`setScope`·`setValue`·`nudge`·`pickAt`·`undo`·`css`·`setCss`·`lint`·`overlaps`·`projectSnapshot`·`settled`). 스모크 시험이 이 창구로 사람 편집을 재현한다.
- 에이전트(Claude Code·Codex)는 시트를 만들 때마다 임시 페이지·스크립트를 새로 짰다(2026-10-18 문자 재료 맞춤: 비교 페이지·확대 페이지·잉크 일치 스크립트). 같은 일을 사람 화면과 같은 도구로 해야 결과를 함께 볼 수 있다.
- 지켜야 할 규칙: master 병합·공개·배포는 사람 승인(AGENTS.md §Git), 원격 push 없음, 검증 부하 예산(MEMORY 2026-10-12·13, `machine_slots.py`), 수치가 아니라 실제 화면으로 판정(MEMORY 2026-10-13), LLM 판정은 선택(MEMORY 2026-10-16), 내보내지 않는 파일은 서비스하지 않음(tailnet 노트 2026-10-13).

## Decision

### 1. 무엇을 만드나
- **개발·검수 사이트**(devsite)는 이 저장소의 내부 도구로 시작한다. 위치는 `devsite/`(Go 모듈 하나)이고, npm 패키지(`package.json` `files`)와 공개 저장소 내보내기(`.gitattributes` export-ignore)에서 뺀다. 지금은 공개 사이트(font.tty.link)를 대신하지 않는다.
- 나중에 같은 서버·작업실이 **대외 서비스**(사용자가 자기 글꼴을 만들고, 우리가 저장해 외부에 서빙)가 된다(§7). 그래서 저장소 전용인 부분(git·worktree·명령 실행)과 서비스에도 쓰일 부분(글꼴 저장·작업실 호스팅·서빙·검수)을 처음부터 층으로 나눈다.
- 할 일: (1) 검수 — 실제 크기 시트, 전후 비교, 감사, 사람 판정 기록. (2) 편집과 반영 — 모든 기본 제공 글꼴을 마우스·수치로 고치고 저장소 파일에 쓴다. (3) 에이전트 — 같은 조작과 검수를 HTTP API·CLI로.

### 2. 서버는 Go, 일은 기존 도구에 맡긴다
- Go 표준 라이브러리(`net/http`, `embed`)로 HTTP·파일·git·작업 대기열·실시간 알림(SSE)·권한을 맡는다. 화면은 바이너리에 묻는다(`embed.FS`). 무거운 웹 프레임워크를 쓰지 않는다.
- 글꼴 모델·검사는 다시 짜지 않는다. 오래 사는 일꾼 둘에 맡긴다.
  - **Node 일꾼** — `authoring/`(글꼴 계약 검사, 선언 단위 diff, 디자인 검사).
  - **브라우저 일꾼** — 저장소 `.venv`의 Playwright Chromium 한 개. 에이전트의 작업실 조작 실행, 시트 PNG·잉크 지표.
- 정적 렌더러는 Go 렌더러(`renderers/go/fontkku`)를 그대로 불러 정적 출력 칸과 정적·런타임 정합 비교에 쓴다.
- 검증·감사·재생성은 정해진 명령 목록(argv 고정)으로만 돌린다. 임의 셸 실행은 없다. 무거운 작업은 한 번에 하나, 측정 일꾼은 `machine_slots.py` 풀을 쓴다.

### 3. 바인딩과 권한
- 기본 `0.0.0.0:8490`(사용자 결정 2026-10-18 — tailscale IP로도 붙는다). 포트·주소는 설정으로 바꾼다. 8470 nginx 미리보기는 당분간 그대로 둔다.
- 0.0.0.0은 LAN에도 열리므로 **읽기와 쓰기를 나눈다**.
  - 읽기: 누구나. 다만 내보내지 않는 파일(`MEMORY.md`·`AGENTS.md`·`CLAUDE.md`·`SSOT.md`·`PLAN.md`·`docs/NOTES/`·`docs/REVIEW/`·`.git`·`tmp/`의 devsite 밖)은 nginx 거절 규칙과 같이 404다.
  - 쓰기(저장·작업 실행·세션·판정): 신뢰 대역(루프백, tailscale CGNAT `100.64.0.0/10`)의 브라우저는 처음 열 때 쿠키를 받는다. 그 밖(LAN)은 서버가 시작할 때 찍는 짝 맺기 주소(토큰)로 한 번 연결해야 한다.
  - 에이전트는 로컬 토큰 파일(`tmp/devsite/agent-token`, 저장소 밖으로 안 나감)을 헤더로 보낸다.
  - 모든 쓰기 요청은 `Host`·`Origin` 검사(DNS 리바인딩·교차 사이트 요청 막기)와 CSRF 헤더를 거친다.
- **사람 전용**: master 반영, 세션 삭제, 설정. 브라우저 세션에서 확인 대화상자를 거친 요청만 받고, 에이전트 토큰으로는 거절한다(AGENTS.md §Git — master 병합은 사람 승인).

### 4. 반영은 편집 세션으로
- 고치는 곳은 master 작업 트리가 아니라 **편집 세션**이다. 세션 하나 = git worktree `tmp/wt-<이름>` + 브랜치 `edit/<이름>`(nginx `/wt/<이름>/` 별칭과 같은 자리)이고, 기준 커밋을 적는다.
- 저장은 세션의 원본 파일에 바로 쓴다(글꼴 CSS `profiles/<id>.css`, 디자인·묶음·그림 문서·자소판은 PLAN의 파일 종류 표). 원자적 쓰기, `If-Match` 판 번호로 덮어쓰기 충돌을 막는다.
- 저장 뒤 파이프라인: 계약 검사 → 이 파일에 기대는 생성물 다시 쓰기(`regen.py --write`, 승인 항목 `layout-stamps`·`element-layer` 제외 — 기준선을 몰래 다시 쓰지 않는다) → 빠른 검사. 결과를 그 저장에 붙인다.
- **반영 단계**: (1) 세션 저장 — 미리보기·검수에 바로 보인다. (2) 세션 커밋 — `edit/<이름>` 브랜치. (3) master 반영 — 사람이 병합 전 목록(바뀐 출력·결정 대기·검증 요약)을 보고 누른다. `merge --no-ff`, push 없음.

### 5. 사람과 에이전트는 같은 편집 경로
- 사람: 작업실(`studio/`, 세션의 판)을 `mount`로 싣고 `shippedSave`를 켠다. 작업실의 직접 조작(끌기·손잡이 틀·키)과 수치 입력을 그대로 쓴다. 작업실의 저장 창구를 devsite HTTP로 바꿔 끼우고, 작업실 자동화 계약 v1의 `change` 사건마다 서버에 저장한다(자동 저장, [PLAN-STUDIO-002](../PLAN/studio-redesign.md) S1·S2). 계약 v1 전에는 호스트가 `FontStudio.css()`를 받아 저장한다(CSS 편집만 담긴다).
- 에이전트: 같은 작업실을 브라우저 일꾼에서 띄워 **같은 자동화 창구**(계약 v1 `FontStudio.api` — `select`·`edit`·`undo`·`snapshot`, 결과·거절 코드를 돌려줌)로 조작한다. 조작 묶음 `ops`(고르기·범위·값·밀기·되돌리기)를 보내면 적용된 것·거절된 것(사람 화면과 같은 거절 사유)·선언 diff·검사·겹침·전후 이미지를 돌려준다. `dryRun`은 저장하지 않고 미리 본다. CSS 원문을 직접 고쳐 저장하는 길도 같은 저장 파이프라인을 탄다.
- 저장마다 **편집 기록**(누가 — 사람·에이전트 이름, 무엇을 — 선언 diff, 왜 — 메모)을 남긴다. 다른 쪽 화면에 SSE로 바로 알린다(에이전트가 고치는 것을 사람이 실시간으로 본다. 사람 쪽 작업실은 "다른 행위자가 바꿈 — 다시 싣기"를 보인다).
- 응답의 이미지는 URL과 함께 로컬 경로를 준다 — 에이전트가 PNG를 직접 열어 본다.

### 6. 검수는 실제 화면, 판정은 사람
- 시트는 브라우저 렌더다. 축: 글꼴 × 기준(master·직전 공개판·브랜치·세션) × 크기(16·24·48·120px) × 글 세트 × 꾸밈 × 바탕. 기준 판의 런타임·CSS는 git에서 바로 읽어(`/ref/<커밋>/…`) 같은 페이지에 나란히 그린다. 어떤 판이든 체크아웃 없이 비교한다.
- 판정은 시트 열쇠마다 사람 판정과 에이전트 의견을 **따로** 적는다. 에이전트 의견은 사람 판정을 대신하지 않는다(MEMORY 2026-10-13·16). 공개 승인 요청(ADR-022 §6)에 보일 묶음(전후 시트·결정 대기·검증 요약)을 한 화면으로 만든다.
- 이미지 캡처는 창 크기만큼 찍는다 — `full_page` 캡처는 잘라 그린 잎을 빠뜨린다([문자 재료 노트](../NOTES/glyph-material-fit-2026-10-18.md)).

### 7. 대외 서비스로 넓힐 수 있게 지금 정해 두는 경계
서비스 자체(계정·결제·운영)는 이번 범위가 아니다. 다만 다음은 처음부터 이렇게 만들어, 나중에 바꿔 끼우기만 하면 되게 한다.

| 경계 | 지금(내부) | 나중(서비스) | 지금 정해 두는 것 |
|---|---|---|---|
| 글꼴 이름 | `gothic`, 세션 `edit:<이름>` | 사용자 글꼴 | API의 글꼴 참조를 처음부터 **이름공간/글꼴**로(`repo/gothic`, `session:ggot/gothic`, 나중 `u:<사용자>/<글꼴>`). 런타임에 걸리는 글꼴 id는 런타임 규칙(`^[a-z0-9][a-z0-9-]*$`) 안에서 전역으로 겹치지 않게 내려 준다(예 `u-<사용자>-<글꼴>`). 작업실의 이름 바꾸기가 범위 선택자를 함께 바꾼다 |
| 저장 단위 | 저장소 파일(`profiles/<id>.css` 등) | 사용자 글꼴 | **글꼴 묶음**(PLAN의 '대외 서비스 확장 경계') — 글꼴 CSS·그림·디자인·출처·바탕 판·런타임 판을 한 덩어리로. 저장소 글꼴은 `spec/fonts.json`에서 묶음 정보를 끌어낸다 |
| 저장 백엔드 | git worktree(판 = 커밋) | 객체 저장소 + 메타 DB(판 = 내용 해시 스냅숏) | Go 인터페이스 `FontStore`(읽기·쓰기 `If-Match`·판 목록·고정 판 읽기). 저장소 판과 서비스 판이 같은 API를 탄다 |
| 신원·권한 | 사람 한 명 + 에이전트 토큰 | 사용자 계정·공유 | 행위자 `{kind: human|agent|service, id}`와 정책 함수(글꼴마다 owner·editor·viewer, 공개·비공개)를 처음부터 둔다. 내부 정책은 그 함수의 한 구현이다 |
| 서빙 | `/repo/`·`/s/<세션>/` | 외부 페이지가 쓰는 글꼴 주소 | 판 고정 주소 `/f/<이름공간>/<글꼴>@<판>/font.css`(영구 캐시)와 `@latest`(짧은 캐시·되돌림). 런타임 `fontBase` 자동 로딩과 `loadFont(href)`가 그대로 쓴다. 정적 HTML이 필요하면 Go 렌더러 `FontDefinition`으로 같은 글꼴을 그린다 |
| 남이 쓴 CSS의 안전 | 우리 글꼴만 | 사용자가 쓴 CSS를 남의 페이지가 싣는다 | **게시 검사**(엄격 단계): 글꼴 계약 검사에 더해 규칙은 그 글꼴의 `:where([data-fy-font="<id>"])` 범위 안만, `--fy-*`와 계약이 허용한 속성만, `@import`·바깥 `url()`·고정 위치·거대 크기 거절, 그림은 SVG 허용 목록(`sanitizeSvg`)·PNG 다시 인코딩. 내부 저장은 지금처럼 경고만, 게시는 엄격 단계가 통과해야 한다 |
| 작업실 | 저장소 판 작업실 + 서버 저장 | 서비스 작업실 | 작업실의 저장을 **저장 창구**(store adapter) 하나로 모은다 — 로컬(초안·파일), devsite(HTTP), 서비스(같은 HTTP + 사용자 인증). 작업실 재설계([PLAN-STUDIO-002](../PLAN/studio-redesign.md) S2)의 항목이다 |
| 런타임 판 | 저장소 작업 트리 | 오래 서빙되는 글꼴 | 묶음에 만든 런타임·계약·배치 revision을 적는다(ADR-031 저장 환경). 서빙은 그 판의 런타임으로 그린 검수 시트를 함께 둔다. 런타임이 바뀌면 다시 검수 표시 |
| 서버 구성 | `cmd/fkkdev`(전부) | `cmd/fkksvc`(서비스 부분만) | Go 패키지를 층으로: `store`·`auth`·`serve`·`review`·`studiohost`(서비스 가능)와 `repo`·`jobs`·`agentops`(저장소 전용). 서비스 바이너리는 앞의 층만 묶는다 |
| API | `/api/…` | 바깥 클라이언트 | 처음부터 `/api/v1/`, 자원 모양은 위 이름공간 참조로 |

서비스를 시작할 때 따로 ADR을 쓴다(계정·저장 위치·과금·약관·신고·삭제·서빙 비용). 이 ADR은 그때 갈아 끼울 이음매만 정한다.

## Consequences

- 좋아지는 것:
  - 브라우저 편집이 저장소에 반영된다.
  - 사람·에이전트가 같은 시트와 같은 편집 기록을 본다.
  - 에이전트는 임시 스크립트 대신 API를 쓴다.
  - 전후 비교 기준을 아무 커밋이나 고를 수 있다.
- 비용:
  - Go 모듈 하나와 일꾼 둘(Node·Python Playwright)을 돌볼 몫.
  - 0.0.0.0 노출 때문에 권한 계층이 필요하다.
  - 세션마다 worktree 디스크가 든다.
- 남는 위험:
  - HTTP라 브라우저 보안 컨텍스트가 아니다(클립보드 읽기 등은 폴백). 서버가 저장하므로 File System Access는 필요 없다.
  - 사람 작업실의 되돌리기 기록은 다른 행위자의 저장으로 다시 실으면 끊긴다.
  - 브라우저 일꾼 하나가 대기열의 병목이다(세션별로 차례를 지킨다).

## Alternatives

- **nginx + 브라우저만**: 파일 반영·작업 실행·에이전트 API가 안 된다.
- **Node 서버**: 저장소의 JS 모델을 바로 쓰는 장점이 있다. 사용자가 Go를 원했고, 단일 바이너리·표준 라이브러리 HTTP·Go 렌더러 재사용 때문에 Go로 한다. JS 모델은 Node 일꾼으로 쓴다.
- **에이전트용 별도 편집 엔진(CSS 직접 계산)**: 사람 화면과 결과가 갈린다. 작업실 자동화 창구 하나로 모은다.
- **master 작업 트리에 바로 저장**: 빠르지만 되돌리기·검토·승인 규칙과 부딪친다. 세션 브랜치로 한다.
- **tailscale serve·tsnet(HTTPS·신원)**: 2026-10-09 사용자가 IP 바인딩을 골랐고, 이번에도 0.0.0.0을 허용했다. HTTPS는 나중에 `tailscale cert` 파일로 붙일 수 있게 남긴다.

## 열린 결정 (기본값)

1. 위치 `devsite/`, npm·공개 저장소 제외 — 기본값 그대로.
2. 포트 8490 — 바꿀 수 있다.
3. LAN 쓰기는 짝 맺기 토큰, 루프백·tailscale은 자동 — 기본값.
4. 에이전트 권한: 세션 만들기·편집·의견·세션 브랜치 커밋 허용, master 반영·세션 삭제·설정은 사람만.
5. 판정 기록은 `tmp/devsite/`(커밋 안 함). 원하면 세션 커밋에 `docs/REVIEW/` 기록으로 싣는다.
6. 8470 nginx는 유지, devsite가 미리보기를 다 맡으면 정리 여부를 묻는다.
7. 대외 서비스의 글꼴 id 규칙(`u-<사용자>-<글꼴>` 꼴)과 판 고정 주소 모양 — 기본값은 §7 표, 서비스 ADR에서 확정.
