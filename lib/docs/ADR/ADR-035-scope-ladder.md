# ADR-035: 편집 범위 사다리 — 좁은 범위가 늘 이긴다

## Status
Accepted (2026-10-19, 사용자 "병합"). 브랜치 `feat/studio-s4a`에서 구현하고 통합 브랜치 `feat/studio-s4`를 거쳐 master에 로컬 병합했다(`2f79fa8`, 병합 전 결정 12–18 모두 기본값). 2026-10-18 Proposed(PLAN-STUDIO-002 S4, ⚑4 기본값: "좁은 범위를 특이도 대신 쓰는 자리로 이기게 한다(엔진 B2와 함께). 옛 CSS는 그대로 읽고, 작업실이 새로 쓰는 CSS 모양만 바뀐다".

## Date
2026-10-18

## Context
- 작업실의 편집 범위는 일곱(자리 가족 · 이 자리 모두 · 이 자리의 이 자모 · 이 자모 어디서나 · 같은 짜임 모두 · 문맥 · 이 글자만)과 고정 모양의 원칙 범위다. [ADR-030 §7](ADR-030-one-engine-glyph-shapes.md) 4단계는 같은 짜임·이 글자만을 문맥 보정 `--fy-ctx-*`에 썼다('새 공개 변수는 없다').
- 그래서 좁은 범위가 먼저 만든 넓은 규칙에 졌다. 문맥 규칙(`:has()`, 특이도 0,5,0) 뒤에 같은 짜임·이 글자만(0,4,0)을 고르면 'specificity'로 거절했다. gothic·sebul·retro 모두 그랬다([작업실 검토](../NOTES/studio-review-2026-10-18.md) D3).
- 엔진 간결화 검토 B2: 좁은 범위를 고치는 길이 둘이다. 하나는 자리 변수를 노드에서 다시 적는 것(절대)이고, 다른 하나는 `--fy-jamo-*`·`--fy-ctx-*` 보정(누적)이다.
- [ADR-008](ADR-008-font-contract-v2.md) §1의 규칙이 이미 답을 준다. "같은 변수는 대체되고, 누적이 필요한 보정은 레벨 전용 변수로 분리한다."

## Decision
1. **사다리**(넓은 것부터): 자리 가족 < 이 자리 모두 < 이 자리의 이 자모 < 이 자모 어디서나 < 같은 짜임 모두 < 문맥 < 이 글자만. 범위 id는 그대로다(`family`·`slot`·`slotJamo`·`jamo`·`case`·`context`·`glyph`, 고정 모양 `principle`).
2. **보정 수준마다 제 변수.** 같은 짜임 모두는 `--fy-case-*`, 이 글자만은 `--fy-syl-*`다. `--fy-glyph-*`는 페이지·런타임의 `--fy-glyph-gap/width/height/index/text`와 부딪쳐서 쓰지 않는다.
   - 접미사는 `--fy-ctx-*`와 같다: 위치 `dx`·`dy`, 비율 `scale-x`·`scale-y`, `rotate`, `size`, `weight`, `stroke`, `clip`, 문자 매핑 `glyph-text`·`glyph-candidate`.
   - 수준은 context, 계층은 `@layer font-kku.context`, 선언은 글꼴이 한다.
   - 공개 변수가 910개에서 932개로 늘었다(기본 CSS 822개 → 840개).
3. **합치는 법**(코어 `font-kku.css`, 런타임 읽기):
   - 위치·회전·획 두께는 jamo + case + ctx + syl로 더한다.
   - 크기·비율은 곱한다.
   - 굵기·자르기는 좁은 것이 대체한다: page ?? syl ?? ctx ?? case ?? jamo ?? slot.
   - 문자 매핑은 page, tune, syl, ctx, case, jamo, slot, font 차례로 찾는다.
   - 고르지 않으면 출력이 그대로다.
   - 고정 모양의 shape 계층은 바탕 글꼴의 case·syl 보정도 비운다.
4. **선택자 특이도와 상관없이 좁은 범위가 이긴다.**
   - 보정 범위(이 자모 어디서나 … 이 글자만)는 서로 다투지 않고 더해진다.
   - 절대 범위(자리 가족·이 자리 모두·이 자리의 이 자모)는 더 좁은 규칙이 같은 자리 변수를 다시 적으면 가려진다. 이것은 사다리가 뜻한 대로다. 작업실은 거절 코드 `EDIT_BLOCKED`를 그대로 쓴다.
   - 그 거절은 가린 규칙의 범위 이름(`Model.ladderRung`)을 말한다. 이 자모에 먹는 가장 가까운 좁은 범위도 권한다: 화면의 '… 범위로 고치기' 단추와 거절 결과의 `suggestScope`.
5. **옛 CSS는 그대로 읽는다.**
   - 예전 작업실이 같은 짜임·이 글자만 틀에 쓴 `--fy-ctx-*`는 그대로 문맥 보정이다.
   - 같은 틀을 다시 고치면 같은 규칙에 `--fy-case-*`·`--fy-syl-*`를 더하고, 옛 선언은 고쳐 쓰지 않는다.
6. **고정 모양(세벌식·직결식).** 원칙 범위 < (직결식) 같은 짜임 모두 < 이 글자만이다. 넓은 범위는 좁은 손 보정을 뺀 모양 값에서 시작한다. 전에는 노드 값에서 시작해서, 이 글자만의 차이가 짜임 전체로 퍼졌다.
   - 세벌식에 '이 자모 어디서나'(range `jamo`)를 더한다.
   - 이 범위는 tune 계층의 `--fy-jamo-dx/dy/size/scale-x/scale-y`(와 회전·굵기·획·자르기)를 짜임 속성이 없는 선택자에 쓴다.
   - 그래서 모든 짜임에 같은 보정을 더하고 모양의 원칙을 깨지 않는다. 쉬운 모드에서도 고를 수 있다.
   - 직결식은 원칙 범위가 곧 이 자모 어디서나라서 둘을 묶는다.
7. **맞춘 자리에서 시작.**
   - 짓는 방식 맞춤([ADR-034 §5](ADR-034-composition-modes.md))이 옮긴 노드는 자리를 밝히면 맞춤이 꺼진다. 그래서 절대 범위에 처음 적을 때 지금 보이는 자리에서 시작한다.
   - 런타임의 새 읽기 API `FontKku.splitFit(node)`가 CSS 자리 그대로의 잉크 상자와 맞춤이 그린 잉크 상자를 준다.
   - 같은 편집에 가로·세로 위치를 함께 적고, 배율이 다르면 배율도 적는다(`Model.applyTarget`의 `freeze`).
   - 값 칸의 '보이는 값'도 그 옮김을 넣는다.
8. **보정 범위의 크기·비율은 배수다.**
   - 크기에 em·px 길이를 적으면 지금 보이는 크기에 맞춘 배수로 바꾼다.
   - 그 밖의 값(%·비율에 길이·글)은 `VALUE_INVALID`(kind `factor`)로 거절한다.
   - 값 칸·`FontStudio.setValue`·`api.edit`의 `set` 모두 그렇다.

## Alternatives Considered
### 계층을 더 나누기(`font-kku.case`·`font-kku.glyph` 레이어)
- 장점: 대체 의미가 그대로다.
- 단점: 계층 차례는 처음 선언한 순서로 정해진다. 그래서 옛 글꼴의 세 계층 문장이 코어보다 먼저 실리면 차례가 어긋난다. 중첩 계층은 바깥 계층의 맨 규칙에 진다. 또 좁은 범위가 넓은 범위의 나중 변경을 가린다(절대값).

### 같은 `--fy-ctx-*`에 이기는 선택자(특이도 부풀리기)
- 장점: 새 변수가 없다.
- 단점: ⚑4가 피하려던 특이도 싸움이다. 손으로 쓴 문맥 규칙이 더 구체적이면 다시 진다.

## Consequences
### Positive
- 범위를 어떤 차례로 고쳐도 좁은 범위의 결과가 보이고, 넓은 범위의 나중 변경도 따라온다(누적).
- 모든 글꼴 모양이 같은 사다리를 쓴다(ADR-030 §7 "같은 편집 범위와 값").

### Negative
- 공개 변수가 22개 늘었다. 코어 합치는 식이 길어졌다(위치·변환에 항이 둘씩).
- 같은 짜임 모두·이 글자만이 쓰는 CSS 모양이 바뀐다. 이번 작업실이 쓴 글꼴 CSS는 이번 런타임이 있어야 그 보정을 그린다.
- 고정 모양의 원칙 범위·이 글자만은 여전히 절대 모양 값이다. 이 글자만은 원칙 범위의 나중 변경을 따라가지 않는다(좁은 것이 이긴다는 뜻은 지킨다).
