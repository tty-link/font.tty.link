# ADR-029 라이브러리 제작 모듈과 사이트 원본 분리

## Status

Accepted — 2026-10-16 사용자 승인으로 개발 master와 사이트 main에 로컬 병합. npm 공개·배포·Pages 전환은 별도 승인 대상.

## Date

2026-10-16

## Context

사이트 원본과 제작 모델이 `site/`에 함께 있어, 라이브러리의 CSS 계약 검사도 사이트 폴더의 코드를 사용했다. 작업실·비교·개발 도구 화면은 사이트 이용자에게 제공하는 기능이며, 그 존재만으로 사이트 원본을 라이브러리 저장소에 함께 둘 필요는 없다. 2026-10-16 사용자는 이 경계를 지적하고 재설계안 저장 뒤 구현 진행을 지시했다.

[ADR-009](ADR-009-font-editor-v2.md)의 CSS 왕복 편집·정적 실행·공개 API 사용 원칙은 유지한다. 작업실을 저장소 내부 도구로만 취급하던 배포 범위는 선택형 라이브러리 UI로 넓히는 방안을 구현한다.

## Decision

### 라이브러리와 사이트의 소유권

font-kku는 런타임·글꼴·명세와 공용 제작 모델·검사·작업실 UI를 관리한다. 사이트 저장소는 소개·사례·문서 페이지·비교 화면·메뉴·페이지 시험과 사이트 빌드를 관리한다. 사이트는 패키지 배포물을 소비하고, font-kku의 생성기나 시험은 사이트 checkout을 읽거나 수정하지 않는다.

제작 모델은 `authoring/`, 작업실 UI는 `studio/`에 둔다. `authoring/themes-data.js` 등 공용 자료는 명세에서 생성한다. 런타임에서 제작 모델이나 작업실을 자동으로 불러오지 않는다.

### 선택형 배포 진입점

우선 `@tty.link/font-kku` 패키지 안에 `./authoring`과 `./studio` 선택 진입점을 추가한다. CommonJS·ESM과 직접 사용할 classic script 자산을 함께 제공한다. 별도 npm 패키지나 독립 버전 체계는 이번 이전에 도입하지 않는다.

`./authoring`은 DOM·렌더러 초기화 없이 편집·검사 모델을 제공한다. 런타임이 필요한 연산은 기존 공개 API를 사용한다. `./studio`는 패키지의 독립 작업실 문서를 호스트가 지정한 영역에 붙이는 `mount()`를 제공한다.

### 작업실의 문서 격리

작업실은 패키지에 포함된 `studio/index.html`을 iframe 안에서 실행한다. 각 인스턴스의 전역 객체·DOM·스타일·런타임 등록부를 격리해 기존 편집 동작을 보존한다. 호스트는 자산 URL, 글꼴, 초기 문장·프로젝트와 제한시간을 전달한다.

핸들은 `ready`, `exportProject()`, `loadProject()`, `getCss()`, `setText()`, `setBoundaries()`, `destroy()`를 제공한다. 부모·프레임 통신은 인스턴스 채널·발신 window·origin을 확인한다. 시작 실패와 요청은 제한시간 안에 종료되며, `destroy()`는 대기 중 요청과 이벤트를 해제한다.

저장 프로젝트 형식과 기본 초안 키는 유지한다. 호스트가 독립 초안을 원하면 `draftKey`로 이름을 정하고, 외부 저장은 프로젝트 읽기·쓰기 API로 연결한다. iframe을 쓰므로 호스트 CSS가 작업실 내부에 직접 적용되지는 않는다.

### 패키지와 사이트 빌드

사이트는 정확한 패키지 버전이나 개발용 로컬 tarball을 사용한다. tarball만으로 사이트를 빌드해 누락된 패키지 파일이 로컬 소스 연결로 가려지지 않게 한다. 사이트의 소스와 생성 출력은 다른 경로에 둔다.

사이트 빌드는 패키지 자산을 `/lib/`에 배치하고, `skills/font-kku-use/`는 기존 `/lib/skill/` 주소로 제공한다. 기존 페이지·공개 문서·README 그림 경로는 유지한다. 사이트가 사용하는 공개 문서와 기존 공개 그림 두 장은 패키지에 포함하되 개발 기록·에이전트 설정은 포함하지 않는다.

font-kku의 기존 사이트 내보내기 명령은 종료해 `--force`로도 사이트 원본을 덮어쓰지 못하게 한다. 사이트 링크·배포 폴더 보호 시험은 사이트 저장소로 옮기고, 라이브러리는 패키지 자산·선택 모듈·독립 UI의 참조를 검사한다.

### 검증의 소유권

라이브러리의 브라우저 회귀 시험은 최소 시험 호스트와 독립 작업실에서 실행한다. 소개·사례·메뉴·웹 앱·공개 페이지 시험은 사이트 저장소에서 계속 실행한다. 검증을 옮기는 동안 기존 판정·임계·글꼴 기준선은 유지한다.

[ADR-022](ADR-022-npm-name-and-versioning.md)의 npm 공개와 사이트 배포 순서를 따른다. 같은 판 번호를 쓴 로컬 후보 tarball은 개발 검증용이며, 새 공개 모듈을 배포하기 전에 버전을 올리고 공개 관문을 통과해야 한다. Pages의 배포 브랜치·호스팅 설정은 별도 승인 후 전환한다.

## Consequences

사이트와 라이브러리는 상대 저장소 없이 빌드·검증할 수 있다. 작업실은 다른 페이지에서도 사용할 수 있고, 사이트는 공개 계약을 사용하는 실제 소비자가 된다.

선택 모듈과 삽입 API를 새 공개 계약으로 관리해야 한다. iframe의 내부 스타일·스크롤·저장 환경을 별도 문서 경계로 다루며, 사이트의 전체 작업 흐름 시험도 독립적으로 유지해야 한다.
