# ADR-020: 렌더 갱신·효과 소유권·로딩 복구·공통 렌더 계획

## Status
Accepted

## Date
2026-10-11

## Context

[설계 검토](../REVIEW/2026-10-11-design-flexibility-review.md)에서 부분 벡터 세트의 자모 누락,
스타일 변경 뒤 오래된 SVG, 효과 정리의 충돌, 복구할 수 없는 자동 로딩 실패를 재현했다.
크기와 간격만 바뀌어도 전체 트리를 재생성하며, 다중 언어 출력의 Unicode 정책과 구조 판단도
충분히 공유되지 않았다. 기존의 빌드 없는 배포와 공개 DOM 계약을 유지하면서 경계를 보강한다.

## Decision

### 1. 자모별 재료와 벡터 갱신

호스트의 `data-fy-material="vector"`는 선택한 세트를 나타내고, 실제 SVG가 있는 자모에만 `data-fy-vector-cell="r<행>-<자모>"`을 붙인다. `sprite` 글꼴의 배치·지원 자모 종류를 유지하면서 그 세트가 제공하는 그림만 교체한다.

예를 들어 `가나`를 표시할 때 `r0-ㄱ`만 등록해도 된다. `ㄱ`은 등록한 SVG, `ㄴ`·`ㅏ`는 기반 자소판으로 표시한다. 기반 글꼴이 마스크 칠을 쓰면 누락 칸의 마스크도 유지한다. 기반 글꼴의 지원 종류 밖에 있는 자모는 기존 기기 글꼴 대체 표시를 따른다. 부분 세트는 정상 입력이며 모든 칸을 완성한 뒤 등록할 필요가 없다. 빈 세트나 도형이 없는 칸은 등록 오류로 진단한다.

이 구분은 **벡터 그림이 없는 자모까지 투명하게 숨기던 문제**를 해결한다. 원문 텍스트는 계속 남고, 실제 SVG가 있는 노드만 벡터용 글자 숨김 규칙을 받는다. 다만 기반 자소판 파일 자체의 누락·잘못된 내용이나 기기의 글꼴 부재를 자동으로 수리하는 기능은 아니다.

`refreshAll(root)`은 호스트 구조뿐 아니라 벡터 자모의 계산된 `--fy-sprite-row`를 다시 읽는다. `r0-ㄱ`에서 `r1-ㄱ`으로 바뀌면 해당 SVG만 교체하고, 선택한 칸이 세트에 없으면 SVG와 표식을 제거해 자소판 표시로 돌아간다. 같은 칸을 계속 선택하면 SVG를 유지한다. 자모의 위치·역할·부모 노드는 그대로 둘 수 있다.

행 선택을 다시 검사하는 것과 CSS를 자동으로 감시하는 것은 별개다. 기존 stylesheet load·호스트 class 변경 경로는 유지하지만, CSSOM·`<style>` 내용·직접 설정한 행 변수 등 임의의 스타일 변경을 모두 관찰하지 않는다. 그런 변경 뒤에는 `refreshAll(root)`으로 반영한다. 색·위치처럼 CSS만으로 바뀌는 값에는 SVG 재생성이 필요하지 않다. `refresh(host)`는 기존처럼 명시적 전체 다시 그리기다.

### 2. 변경 종류에 맞는 갱신

같은 글자의 크기를 바꿀 때는 이미 만들어 놓은 글자·자모 노드를 계속 쓴다. 표시할 글자나 조합 구조가 바뀔 때는 관리 트리를 다시 만든다. 이를 위해 자동 속성 갱신(`reason: attribute`)에서 원문·정규화된 글꼴·자모 세트·명시/계산된 획 깊이·표현 모드·자모 깊이·재료 메타데이터·씨앗값·자모 씨앗 옵션을 비교한다. 이 값이 같고 기존 관리 root가 있으면 바탕 요소 계약만 갱신한다.

| 변경 | 수행하는 작업 | 노드 보존 |
|---|---|---|
| 첫 렌더 | 모델과 관리 트리 생성 | 최초 생성 |
| 원문·정규화 글꼴·자모 세트·구조 설정 변경 | 관리 트리 전체 재생성 | 바탕 요소만 유지 |
| `size`·`spacing`·`wrap-unit`·`animate`의 자동 속성 변경, 위 조건 만족 | 바탕 요소의 확정 속성·CSS 변수 갱신 | 관리 root와 자모 유지 |
| `refreshAll`에서 다른 벡터 칸 선택 | 해당 SVG 추가·교체·제거 | 관리 root와 자모 유지 |
| 글꼴 id/contract만 변경 | 진단용 상태 갱신 | 모두 유지, 렌더 이벤트 없음 |
| 같은 값의 속성 재설정·변화 없는 재해석 | 불필요한 작업 생략 | 유지 |
| 명시적 `render`·`refresh` | 전체 그리기 | 관리 트리 재생성 |

보존은 속성 이름만으로 보장하지 않는다. `seed="auto"`/`"random"` 재해석, 직전 JS 호출의 일회성 옵션에서 속성 값으로 복귀, CSS에 따른 구조 변경이 함께 있으면 크기를 바꾼 경우에도 전체 갱신이 필요할 수 있다. 모든 기존 노드를 비교하는 범용 DOM diff나 문장 일부만 다시 그리는 기능은 이번 결정의 범위가 아니다.

전용 태그는 기존처럼 속성 callback에서 동기로 반영하고, 클래스 방식은 `MutationObserver`가 전달한 변경을 반영한다. `font-kku:render` 이벤트는 유지하되 **전체 노드 교체의 증거가 아니라 갱신 알림**으로 정의한다. 페이지 후처리는 멱등하게 적용한다. 노드 보존 경로에서는 리스너와 DOM 참조가 유지되며, 명시적 `render`/`refresh`는 DOM 후처리 초기화와 효과 재생을 위해 전체 교체 계약을 보존한다.

여러 옵션을 한 번에 적용할 때는 기존 `FontKku.render(host, { size, spacing, animate })`를 사용할 수 있다. 이는 전체 렌더 한 번이며 호출 한 번에만 적용된다. 지속 값은 속성에 기록한다. 별도 batch API나 모든 속성 변경을 지연시키는 새 비동기 대기열은 추가하지 않는다.

#### 측정값을 해석하는 범위

첫 렌더를 마친 `한글` 100회 반복(200음절)의 `size` 속성을 20회 바꾸는 실험에서, `document.createElement` 호출은 **20,080회에서 0회**로 줄었다. 이전에는 한 번에 1,004개 요소를 만들고 이를 20회 반복했으며, 개선 후에는 처음 만든 트리를 재사용했다. 첫 렌더 노드 수를 0으로 만든 결과가 아니다.

이 수치는 새 HTML 요소 생성에 관한 측정이다. 브라우저의 스타일 계산·배치·칠하기, 옵션 해석·이벤트, 모든 메모리 할당이 사라졌다는 뜻은 아니다. SVG 생성량 전체나 실제 제품의 프레임 속도를 측정한 것도 아니다. CSS가 없는 빈 Chromium 페이지의 단일 실행 시간은 58.2ms → 12.2ms였으나 보편적인 속도 향상률로 제시하지 않는다. 구조 변경·명시적 `refresh()`·다른 글꼴과 효과 조합의 비용은 별도로 측정해야 한다. 자세한 조건은 [설계 검토 기록](../REVIEW/2026-10-11-design-flexibility-review.md)에 둔다.

### 3. 효과의 소유권

상호작용 controller는 자신이 소유한 이동·회전·애니메이션 차단·transition만 해제한다.
동시에 활성인 효과는 `magnet > scatter`, 같은 종류는 나중에 생성한 활성 controller가 우선한다.
상위 효과가 끝나면 남은 효과가 다시 나타나고, 마지막 효과가 끝나면 원래 inline 값과
`!important` 우선순위까지 복원한다. 포커스 가능 상태와 공용 상태 클래스도 같은 수명으로 관리한다.

여러 효과의 이동량을 무조건 더하면 각 효과가 가정한 기준 위치·도달 범위가 달라진다.
이번 계약은 예측 가능한 우선순위를 택한다. CSS 움직임은 상호작용이 소유하는 동안 잠시
중단하고 소유권이 사라지면 복원한다.

### 4. 자동 로딩 실패 격리와 복구

글꼴 CSS 요청은 `(Document 또는 ShadowRoot, 실제 URL)`, 자모 모듈 요청은 `(Document, 실제 URL)`로 관리한다. 실패가 같은 이름의 다른 root나 변경된 기준 주소까지 막지 않는다. `FontKkuConfig.fontBase`를 명시하면 스크립트 주소에서 추론한 값보다 우선한다.

내부 요청 상태는 미요청 → `loading` → `ready` 또는 `error`다. 같은 주소에 대해 연결된 요청이 진행 중이면 공유하고, 실패한 주소는 무한히 자동 요청하지 않는다. `FontKku.retryFont(host)`가 현재 주소의 실패 상태를 해제하고 자동 로딩 경로에 다시 들어간다. 기준 주소를 바꾸고 `refresh()`·`refreshAll()` 등으로 확인하면 새 주소는 새 요청이다.

성공한 CSS 링크나 로딩 중인 링크·스크립트를 제거한 경우도 처리한다. 다음 확인에서 연결이 끊긴 요청의 상태를 버리고 다시 요청할 수 있다. 늦게 도착한 이전 요청의 완료·실패 이벤트는 요청 객체가 현재 기록과 같을 때만 상태를 갱신하므로 새 요청을 덮지 못한다. 폰트 CSS와 자모 모듈이 함께 필요하면 두 요청을 독립적으로 시작하며, 하나가 진행 중이라고 다른 요청의 시작을 건너뛰지 않는다.

실패 시 관련 호스트에서 `font-kku:loaderror` 이벤트를 발생시킨다(`bubbles`, `composed`). `detail`은 `{ kind: 'font' | 'jamo-set', name, url, error }`다. 스크립트 로드 자체가 성공해도 요청한 세트를 등록하지 않았으면 모듈 실패로 처리한다. 페이지는 오류 이벤트를 받아 재시도 표시나 다른 글꼴 선택을 제공할 수 있다.

복구 API의 범위는 다음과 같다.

- `retryFont`의 반환값은 대상 요소 또는 `null`이며, 성공을 기다리는 Promise가 아니다. 관리 중인 바탕 요소와 자동 로딩 기준 주소가 필요하고 `autoload: false`이면 요청하지 않는다.
- 재시도도 화면 가까운 요소부터 받는 기존 정책을 따른다. 화면 밖 요소에 호출했다고 즉시 네트워크 요청이 시작된다는 보장은 없다.
- CSS 직접 로딩을 기다리려면 `loadFont(href, { root })`를 사용한다. 이 API는 실패 시 Promise를 reject하고 다음 호출이 재시도한다. 자동 로딩 오류 이벤트와 별도 계약이다.
- 가림막은 성공·실패 또는 제한 시간 뒤 해제한다. 제한 시간이 지나도 요청 자체를 실패로 판정하거나 자동 반복하지 않는다.
- 복구는 요청을 다시 시작하고 상태를 알려 주는 기능이다. 잘못된 CSS 내용·없는 자소판 그림·기기 글꼴 부재를 자동으로 교정하지 않는다.

### 5. 언어 공통 계약

`spec/capabilities.json`은 실행 환경별 정규화·분절·출력·확장 지원 범위를 기록한다.
문자 종류의 number/punctuation 분류는 명세 Unicode 표에서 생성하여 실행 환경의 Unicode
버전 차이가 CSS glyph-kind 선택을 바꾸지 않게 한다. 현재 고정 기준은 Unicode 17.0이며, 그 표 밖의 미래 문자는 명세를 갱신하기 전까지 `symbol`로 처리한다. 한글 한 음절·ASCII 영문·한 코드 포인트의 숫자/문장부호 분류와 여러 코드 포인트를 포함한 글자 묶음을 구분한다. 정규화와 분절에 남는 환경별 차이는
명시적으로 기록하고 모든 기능의 완전한 동일성을 주장하지 않는다.

`spec/render-plan.json`은 깊이별 topology에 맞는 최종 head/초성/중성/종성 자리 계획이다.
기본 placement와 두 depth override를 생성 시 한 번 합성하고, JS 및 네 언어 출력기가
이를 사용한다. 출력기의 자모 선택과 묶음 판단은 이 계획을 따른다. DOM 생성/HTML escaping은
각 backend가 담당하고, 평문 모드는 고유한 2줄 배치를 유지한다. 예를 들어 `과`의 모음을 둘로 나눌지, 통째로 둘지, 초성과 합친 `고`+`ㅏ`로 표시할지에 필요한 최종 자리 수와 head 여부를 공통 계획에서 판단한다. 의미 역할도 같은 명세에서 생성한 값으로 지정한다. 다섯 구현이 하나의 실행 파일을 공유하는 것이 아니라, **같은 구조 판단 자료를 소비하면서 각 언어로 출력하는 방식**이다. 텍스트 모델·DOM/HTML 출력의 차이까지 없애는 전면 재작성은 아니다.

사용자 글꼴 확장은 전역 등록 대신 호출별 글꼴 정의를 전달한다. 지원하는 재료·표현 모드·
깊이를 명시하고 기존 기본 글꼴을 수정하지 않는다. 정적 HTML의 `FontDefinition`은 신뢰할 수 있는 CSS와 명시적 메타데이터를 받는 `system` 재료 글꼴을 지원한다. 브라우저의 벡터 세트 등록·자동 URL 로딩·상호작용 효과를 정적 출력기에 추가한 것은 아니다. 상세 API와 지원 범위는 capability 명세와 다중 언어 문서에 기록한다.

## Alternatives Considered

- 모든 변경에 전체 렌더: 단순하지만 대화형 크기 조정과 자모 효과의 수명을 불필요하게 끊는다.
- 전체 트리 diff: 적용 범위가 크므로 먼저 비구조 속성과 재료 갱신을 분리한다.
- 임의 CSS 변경 전부 자동 감시: 상위 요소·미디어 조건·CSSOM까지 완전하게 감시하기 어렵다.
  load/class 등 기존 자동 경로를 유지하고 그 밖의 변경은 `refreshAll`을 명시한다.
- 로딩 실패 무한 재시도: 존재하지 않는 글꼴도 계속 요청하므로 명시 재시도를 제공한다.
- 모든 Unicode 알고리즘 전면 이식: 번들 크기와 유지비가 크다. 고정 분류와 지원 범위 계약부터
  일치시키며 기존에 알려진 정규화·분절 차이를 숨기지 않는다.

## Verification

각 변경의 회귀 검사, 생성 계획/Unicode 미러 신선도, 기존 DOM 패리티, 실제 패키지 소비자
