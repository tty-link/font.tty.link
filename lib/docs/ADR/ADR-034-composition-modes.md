# ADR-034: 짓는 방식 — 음절 나누기와 자모 조립식을 하나로 고른다

## Status

Accepted (2026-10-18, 사용자 "병합"). C0–C5를 같은 날 브랜치 `feat/compose`에서 구현하고 master에 로컬 병합했다(`47e8ab0`, [PLAN-COMPOSE-001](../PLAN/composition-options.md)).

사용자 요청:
- "화 -> 호+ㅏ, ㅎ+ㅗ+ㅏ, ㅗ+ㅇ+ㅗ+ㅏ 이런식으로 여러가지 방식으로 조합할 수 있는 것도 선택할 수 있는 옵션 있어야 하는데.. 이런것들도 논의 되었었는데 현재 구현 된건지도 모르겠어"
- 상태 보고와 제안 뒤: "응 그렇게 진행해줘. 스튜디오나 내부 사이트에도 잘 반영해야해. 설계 문서 및 공개 문서들에도 반영해줘야하고"
- 옛한글: "옛한글은 지원할 수 있도록 설계에 고려만 하면 되고 TODO 리스트에 추가만 해줘"

구현 순서는 [PLAN-COMPOSE-001](../PLAN/composition-options.md)이다. 상태 조사와 시트는 [글자를 짓는 방식 노트](../NOTES/composition-options-2026-10-18.md)에 있다.

## Context

글자를 짓는 장치는 이미 둘 있다. 다만 따로 있다.
- **음절 나누기**(ADR-024 §2, ADR-030 §4): 음절을 노드 몇 개로 나누나.
  - 모음 `--fy-vowel-depth: split | whole | syllable`, 받침 `--fy-coda-depth: split | whole`, 줄임 `--fy-jamo-depth`.
  - 화: `syllable` = 호+ㅏ, `whole` = ㅎ+ㅘ, `split` = ㅎ+ㅗ+ㅏ.
- **자모 조립식**(ADR-025 §4·§5, `spec/jamo-recipes.json`): 노드 하나를 무엇으로 짓나.
  - 디자인 규칙의 `apply: { method: "compose", recipe }`로 자모마다 고른다. 예: ㅎ = ㅗ+ㅇ(`hieut-circle-o`).

2026-10-18에 화로 확인한 빈 곳은 다섯이다.
1. 두 축을 함께 고르는 하나의 옵션이 없다.
2. 작업실에 나누기 고르기가 없다(변수 값을 손으로 친다).
3. 원소 재료(기본)는 고른 조립식을 따르지 않는다. ADR-025 §5의 "규칙·binding이 고른 조립식은 재료 없이도 따른다"와 다르다.
4. 네모꼴에서 글꼴 기본이 아닌 나누기는 자리가 틀린다(공개판 알려진 문제, 0.1.4-rc.2). 세벌식·직결식은 된다.
5. 공개 사용 안내서(`skills/font-kku-use/`)에 둘 다 없다.

## Decision

### 0. 고르지 않아도 된다
- 사용자 원칙(2026-10-18): "지원하는 모등 기능을 꼭 활용해야 글꼴을 만들 수 있도록 강제하면 안된다는건 중요한 원칙이야. 간단하게도 만들 수 있고, 원하면 세세하게 제어할 수 있게 하는것이 철학인거야. 직접 그리는 글꼴 제작도 그렇고, css 이용해서 사용할 때도 그렇고.."
- 짓는 방식은 원할 때 고르는 것이다. 아무것도 고르지 않으면 `auto`(모양대로)이고 지금 출력 그대로다. CSS·디자인 JSON·작업실 어디에서도 필수 칸이 아니다.
- 프리셋 하나로 충분하다. 축별 고르기·자모별 조립식·지원표는 세세하게 하고 싶을 때만 정밀 모드에서 쓴다.

### 1. 짓는 방식은 두 축의 묶음이다
- **나누기**(음절 → 노드): 모음 `split | whole | syllable`, 받침 `split | whole`.
- **조각 깊이**(노드 → 조각): `none`(자모 그대로) · `pieces`(다른 자모로 — ㅎ = ㅗ+ㅇ, ㄲ = ㄱ+ㄱ) · `origins`(원형 8과 천지인까지 — ㅎ = ㆍ+ㅡ+ㅇ, ㅗ = ㆍ+ㅡ).
- 두 축은 직교한다. 미리 정한 묶음(프리셋)으로 고르고, 정밀하게는 축마다 고른다. 자모마다 고른 조립식(디자인 규칙)은 늘 묶음을 이긴다.

### 2. 프리셋
| 값 | 화면 이름 | 화 | 나누기(모음·받침) | 조각 깊이 |
|---|---|---|---|---|
| `auto`(기본) | 모양대로 | 그 모양의 기본(세벌식: ㅎ+ㅗ+ㅏ) | 모양·글꼴의 기본 | `none`(그림 재료의 기본 조립식은 지금처럼) |
| `syllable` | 음절로 | 호 + ㅏ | `syllable` · `whole` | `none` |
| `whole` | 겹모음 통째로 | ㅎ + ㅘ | `whole` · `whole` | `none` |
| `jamo` | 자모로 | ㅎ + ㅗ + ㅏ | `split` · `split` | `none` |
| `pieces` | 조각으로 | (ㅗ+ㅇ) + ㅗ + ㅏ | `split` · `split` | `pieces` |
| `origins` | 원형으로 | (ㆍ+ㅡ+ㅇ) + (ㆍ+ㅡ) + (ㅣ+ㆍ) | `split` · `split` | `origins` |

- `auto`의 출력은 지금과 같다(기본 출력 불변).
- 조각 깊이의 자모별 조립식은 자료로 정한다: `spec/jamo-recipes.json`에 `levels: { pieces: { 대상: 조립식 }, origins: { … } }`.
  - 검사기가 순환 없음·대상 역할·필수 조각을 본다(ADR-032 §3).
  - 처음 값은 지금 조립식에서 고르고 시트로 정한다: `pieces`는 `hieut-circle-o`·`double-*`·`final-*`·겹모음 `compose`, `origins`는 `hieut-added-lines`·`rieul-lines`·`bieup-lines`·`pieup-lines`·천지인 조각.
  - 그 자모에 해당 깊이 조립식이 없으면 한 단계 위(자모 그대로)로 둔다. 이것은 조용한 대체가 아니라 정의다 — 진단에 "조각 없음"으로 남긴다.

### 3. 고르는 자리와 차례
- CSS: 페이지 `--fy-composition`, 글꼴 `--fy-font-composition`. 깊이 변수와 같은 계층이다(페이지가 글꼴을 이긴다).
  - 한 계층 안에서는 낱 깊이 변수(`--fy-vowel-depth`·`--fy-coda-depth`)가 프리셋을 이기고, 프리셋이 줄임 깊이 변수(`--fy-jamo-depth`)를 이긴다. 줄임 깊이는 그 계층의 일반 기본이고(기본 제공 글꼴이 쓴다), 낱 깊이는 세세한 고침이다(2026-10-18 통합 때 정함 — 작업실이 프리셋 한 줄만 적어도 먹고, 사람이 쓴 낱 깊이는 늘 이긴다).
  - CSS만 쓰는 사람도 디자인 없이 고를 수 있다.
- 디자인 JSON(판 2.1, 더하기): `composition: "<프리셋>" | { preset?, vowel?, coda?, pieces? }`. 규칙의 자모별 조립식이 이긴다.
- 차례(높은 것부터): 자모별 디자인 규칙 > 페이지 CSS(낱 깊이 > `--fy-composition` > 줄임 깊이) > 디자인 `composition` > 글꼴 CSS(낱 깊이 > `--fy-font-composition` > 줄임 깊이) > 모양의 기본(ADR-030 §4, ADR-031 페이지 우선).
- 바탕 요소에 푼 값을 찍는다: `data-fy-composition`(프리셋 또는 `custom`). 나누기는 지금처럼 `data-fy-vowel-depth`·`data-fy-coda-depth`.

### 4. 재료는 모두 고른 조립식을 따른다
- 원소 재료: 조각 자모의 뼈대 획을 대상의 획 묶음 자리(`stroke-set`·`segment-set`·`box`)에 놓는다. 그림·글꼴 재료와 같은 놓기 계산이다. 조각 표시(`data-hoek-letter`·조각 경로)는 실제 조각 자모를 밝힌다. 조각마다 다른 재료를 묶는 것(`bindings`)도 원소에서 된다.
- 그림 세트·글꼴 글자: 지금처럼(시트에서 이미 됨).
- 못 짓는 칸은 진단 `COMPOSITION_UNSUPPORTED`(까닭: 측정·조각·배치 부족)로 남기고 다른 방식으로 몰래 바꾸지 않는다(ADR-032 §6.1).

### 5. 자리 품질이 먼저다
- 네모꼴의 기본이 아닌 나누기(통짜 모음·통짜/낱 받침)도 세벌식처럼 맞는 자리에 놓는다(알려진 문제를 고친다). 고정 모양의 "합친 노드 안 자모는 낱 자리와 같다"(ADR-030 §4)를 네모꼴의 잰 자리에도 쓴다.
- 모양(세벌식·직결식·네모꼴) × 프리셋(6) × 재료(원소·그림·글꼴)의 지원표를 시트로 검수한다. 통과한 칸만 쉬운 모드에 보이고, 안 되는 칸은 까닭과 함께 막는다.
- 기본 출력(`auto`)의 기준선은 바뀌지 않아야 한다. 다른 프리셋의 모습은 시트 승인 뒤 기준선에 더한다.

### 6. 작업실·개발·검수 사이트·자동화
- 작업실 디자인 페이지에 **짓는 방식**을 둔다.
  - 쉬운 모드: 프리셋 그림 단추. 지금 글꼴·재료·모양으로 '화'(와 미리보기 글)를 그려 보인다. 막힌 칸은 까닭을 보인다.
  - 정밀 모드: 모음·받침 나누기, 조각 깊이 고르기, 자모별 조립식 탭(지금 '조립식' 탭), 지원표.
  - 고르면 디자인의 `composition`에 저장된다(글꼴 묶음에 들어감). 하나의 기록 한 줄.
- 자동화 계약: `api.info()`에 `composition`. 고르기는 `api.design.edit`, 그리고 자료만 오가는 `api.setComposition(값)`(mount `call` 가능).
- 개발·검수 사이트: 검수 시트에 '짓는 방식' 글 세트·보기(프리셋 × 글꼴 나란히). 판정 열쇠에 프리셋을 넣는다. 고치기 화면은 작업실을 그대로 쓴다.
- 정적 렌더러 4언어: 나누기 부분은 지금 깊이 지원을 그대로 쓴다. 조각 깊이 `pieces`·`origins`는 처음에는 기본 획을 내고 진단을 남긴다(렌더러 계약에 적는다). 원소 조각 표를 굽는 일은 뒤 단계다.

### 7. 옛한글을 막지 않는다
옛한글은 이번에 구현하지 않는다. 다만 이 설계가 옛한글을 막지 않게 한다(ADR-032 §2.2·§2.3, PLAN-HANGUL-001 H1·H6).
- 나누기와 조각 깊이는 역할 안 자모 **열**(첫가끝 연속)에 대해 정의한다. 현대 완성형 산술 분해를 전제로 하지 않는다.
- 조각 깊이 자료(`levels`)는 이름공간과 판을 가진 선언 자료라 옛자모 조립식을 더할 수 있다. 예: ㆆ = ㅇ + 가획, ㆁ, ㅿ, 아래아 ㆍ, 가변 묶음 ᄢ.
- 지원 결과는 분석·조립식·배치·재료·출력기별로 낸다(ADR-032 §2.3). H6에서 옛한글 표현을 켜기 전에는 옛한글 묶음에 프리셋을 적용하지 않는다. 지금 출력·줄바꿈·선택·복사를 그대로 두고 진단만 남긴다.

### 8. 호환
- 기본(`auto`)과 저장된 디자인(`composition` 없음)의 출력은 그대로다.
- 공개 표면은 더하기만 한다: CSS 변수 둘, 디자인 필드 하나, 바탕 요소 속성 하나, 진단 코드, 자동화 계약 동작 하나, 조립식 자료 `levels`.
- 원소 재료가 고른 조립식을 따르게 되는 것은 **그런 규칙을 저장한 디자인의 출력이 바뀌는 것**이다. 지금은 따르지 않으니 그런 디자인은 드물다. 병합 전 목록으로 묻는다.

## Alternatives Considered
- **깊이 변수만 늘리기**(`--fy-piece-depth`): 조각 깊이를 자모마다 다르게 정할 자료가 없어 결국 조립식 자료가 필요하다. 프리셋 없이 두 축을 따로 두면 지금의 빈 곳 1이 남는다.
- **프리셋을 디자인 JSON에서만**: CSS만 쓰는 사람(대부분의 페이지)이 고를 수 없다.
- **조각 깊이를 뼈대 획 수로 자동 결정**: 제자·모양 재구성·이체(ㄹ)를 구별할 수 없다(ADR-025 §5). 자료로 정한다.

## Consequences
### Positive
- 사용자가 말한 방식(호+ㅏ, ㅎ+ㅗ+ㅏ, ㅗ+ㅇ+ㅗ+ㅏ)을 이름 하나로 고른다. CSS·디자인·작업실·사이트가 같은 이름을 쓴다.
- 원소 재료의 조립식 결함과 네모꼴 나누기 자리 결함을 함께 고친다.
- 옛자모 조립식을 같은 자료에 더할 수 있다.

### Negative
- 지원표(3 × 6 × 3)를 검수해야 한다. 막힌 칸이 남을 수 있다.
- 정적 렌더러는 조각 깊이를 처음에 그리지 못한다(진단만).

### Risks
- 네모꼴 자리 고침이 기존 글꼴의 기본 나누기 출력을 건드린다 → 기본 나누기는 기준선(조립·시각)으로 막고, 새 나누기 칸만 바뀌게 한다.
- 원소 조각 놓기가 획 굵기 규칙·밀도 계수와 부딪친다(ADR-030 단계 2 교훈) → 마지막 모양 값으로 셈하고 겹침·획 굵기 감사를 프리셋마다 돈다.

## 사용자 결정 ⚑ (기본값)
1. 프리셋 이름과 여섯 값 — 위 표대로.
2. 원소 재료가 디자인이 고른 조립식을 따른다(그런 저장 디자인의 출력 바뀜) — 따른다.
3. 네모꼴 기본이 아닌 나누기의 자리 고침(알려진 문제 해결, 그 나누기를 쓴 페이지의 출력 바뀜) — 고친다.
4. 정적 렌더러의 조각 깊이 — 처음에는 진단만.
5. 쉬운 모드에는 지원표 시트를 통과한 칸만 보인다 — 그렇게.
