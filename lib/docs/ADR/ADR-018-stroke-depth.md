# ADR-018: 획 깊이 — 자모 아래 단위(제자원리·획)로 쪼개기

## Status
Accepted (1–3단계 구현, 4단계 연구는 남음)

## Date
2026-10-10 제안 · 2026-10-11 결정

## Context
- 지금 폰꾸가 쪼개는 가장 작은 단위는 자모다. 그 위로는 깊이 선택이 있다.
  - 합자 모음: '화' = ㅎ + ㅘ(통짜) / ㅎ + ㅗ + ㅏ(쪼갬) / '호' + ㅏ(완성형 head)
  - 겹받침: '값' = ㅄ / ㅂ + ㅅ
- 그러나 '하'는 ㅎ + ㅏ뿐이다. ㅎ·ㅋ·ㄲ 같은 자음, ㅏ 같은 모음은 쪼개지지 않는다.
- 사용자 제안(2026-10-10): 기본은 자음·모음 단위로 두고, 고급 기능으로 자음·모음을 더 쪼개 획 단위로 조립하게 하자.
- 이미 있는 바탕:
  - 벡터 자소(ADR-013)는 자모 하나를 SVG 경로 여러 개로 그린다. ㅂ은 2개, ㅅ은 2개, ㄲ은 ㄱ 두 개다.
  - 그러나 경로에 이름·순번이 없고, '붓을 떼지 않는 한 덩어리'라서 획순 단위가 아니다(ㄷ·ㄹ·ㅁ은 한 경로).
- 가독성 감사(같은 날)가 보인 한계: 자모를 통째로 늘이고 줄이면 막대 두께와 내림획 길이가 묶여 움직인다.
  '두'의 ㅜ를 짧게 하려고 누르면 막대가 얇아진다. 그래서 지금은 clip으로 내림획 끝을 자른다.
  획 단위로 놓으면 둘을 따로 정할 수 있다.

## Decision

### 0. 구현에서 정한 것 (제안과 달라진 점)
- **깊이는 두 값** `jamo`(기본) | `stroke`. 제안의 `parts`(부품 묶음 `<g part="hoek-part">`)는 노드를 늘리지 않고 획마다 붙는
  정체성으로 대신한다 — `data-hoek-role`(자음 `base`·`added`·`variant`, 모음 `heaven`·`earth`·`person`),
  `data-hoek-from`(들여온 글자), `data-hoek-letter`(속한 홑자모). 제자원리 보기는 이 속성으로 칠한다.
- **이름 확정**: 노드 `part="hoek"`, 속성 `data-hoek`(자모 안 차례 1부터)·`data-hoek-kind`(정본 종류 코드 `h` `v` `hv` `vh`
  `lf` `rf` `dot` `ring` 그대로), 변수 `--fy-hoek-index`·`--fy-hoek-order`(런타임), `--fy-hoek-dx/dy/rotate/scale-x/scale-y`(페이지).
- **글꼴 레이어(`font-kku.hoek`)는 두지 않는다.** 획 레벨 변수는 페이지 전용이다 — 글꼴 계약(ADR-008)의 레이어 문을 바꾸지 않고,
  획 단위 교정이 필요한 글꼴이 생길 때 다시 정한다. `--fy-hoek-weight`(획 굵기)도 그때 — 벡터 획 굵기는 `[part="vector"]`의
  상속 값이라 획에서 곱하려면 굵기 식 전체를 다시 써야 해 페이지 `stroke-width`를 덮는다.
- **요청할 때만 찍는다.** `data-fy-stroke-depth`와 획 노드 속성은 요청이 있을 때만 생긴다 — 기본 DOM과 사이드카 parity는 그대로다.
- **차례**: 런타임이 그린 뒤 바탕 요소의 획을 문서 순서(글자 → 초성·중성·받침 → 획순)로 세어 `--fy-hoek-order`를 단다.
- **자소판은 그대로.** 생성기는 자소판(SVG)을 `SHAPES`로, 벡터 모듈을 획순 표 `HOEK_SHAPES`(ㄷ·ㄹ·ㅁ·ㅂ·ㅌ 쪼갬, ㅍ·ㅐ·ㅒ·ㅙ 차례)로
  그린다. 쪼갠 획 끝은 기본 끝 늘이기(굵기 절반)가 모서리를 덮어 모양이 같다 — sprite-system 모듈 93칸 렌더가 쪼개기 전과
  픽셀 같다(sprite-example은 이음매 안티에일리어싱 12px).
- 런타임 획순 표(`HOEK_TABLE`)는 `spec/strokes.json`에서 생성한다(`build_jamo_svg.js --write`, `--check`가 대조).

### 원래 제안

### 1. 깊이 세 단계 — `stroke-depth` 옵션(속성 `stroke-depth`, CSS `--fy-stroke-depth`)
| 값 | 단위 | 예 |
|---|---|---|
| `jamo` (기본) | 자모 — 지금 그대로 | 하 = ㅎ + ㅏ |
| `parts` | 제자원리 부품. 자음은 기본자 + 가획·병서, 모음은 천지인 | ㅋ = ㄱ + 획, ㅎ = 꼭지 + ㅡ + ㅇ, ㄲ = ㄱ + ㄱ, ㅏ = ㅣ + ·, ㅛ = ·· + ㅡ |
| `stroke` | 획순대로 한 획씩 | ㄹ = ㅡ, ㄱ꺾임, ㄴ꺾임 … (획순 정본을 따른다) |

기존 합자·겹받침 깊이(vowel/coda depth)와 독립된 축이다. 쪼갠 단위는 **자모 노드 안의 자식 노드**가 된다. 그래서 자모 노드의 자리·slot·역할 계약(ADR-008)과 기존 CSS는 그대로 듣는다.

### 2. 정본 `spec/strokes.json`
호환 자모 51자마다 다음을 적는다.
- 획 목록과 획순
- 획 종류: 가로·세로·삐침·내림·점·동그라미·꺾임
- 부품 묶음: 기본자 / 가획 / 병서 / 천·지·인

자소판 생성기(`scripts/build_jamo_svg.js`의 SHAPES)는 이 정본을 따라 획을 그리도록 다시 쓴다. 획순대로 경로를 나누고, 자리 상자 안 좌표는 지금과 같게 둔다.

### 3. DOM과 CSS
- 벡터 재료: 획마다 `<path part="hoek" data-hoek="2" data-hoek-kind="horizontal" data-hoek-part="가획">`
  - 이름은 `stroke`가 아니라 '획'의 로마자 `hoek`이다. `--fy-stroke`(외곽선 폭)·`--fy-<slot>-stroke`와 겹치지 않게 하려는 것이다. 정식 이름은 결정 때 확정한다.
  - `parts` 깊이는 같은 부품의 획을 `<g part="hoek-part" data-hoek-part="가획">`으로 묶는다.
- 변수: 자모 아래의 새 레벨 `--fy-hoek-dx/dy/rotate/scale-x/scale-y/weight`
  - 보정 합성 규칙(ADR-008: jamo + ctx + page)에 hoek 레벨이 하나 더해진다.
  - 글꼴은 hoek 레이어(`font-kku.hoek`)에서 획 정체성 조건(`[data-hoek-kind]` 등)으로만 선언한다.
- 접근성은 그대로다. 원문은 하나이고, 획 노드는 시각 루트(`aria-hidden`) 안에 있다.

### 4. 재료별 지원
| 재료 | 지원 |
|---|---|
| 벡터 자소 | 완전 지원. 획이 곧 경로다 |
| SVG 자소판 그림 자소 | 같은 정본으로 벡터 세트를 함께 내므로(`module: true`), 획 깊이를 고르면 벡터로 그린다 |
| 기기 글꼴(sebul·gothic) | 기기 글리프는 쪼갤 수 없다. 1단계에서는 `jamo`로 되돌리고 `data-fy-stroke-depth="jamo"`로 알린다. 연구 과제: 같은 글리프를 획 영역으로 잘라 낸 사본 여러 장(글꼴별 영역 교정 필요) |

### 5. 쓰임
- **획순 그리기**: `animate="draw"`가 정식 움직임이 된다(지금은 움직임 페이지의 조리법 카드). 획순대로 차례로 긋는다. 한글 교육·서명·인트로에 쓴다.
- **제자원리 보기**: 기본자와 가획을 다른 색으로 칠한다. "ㅋ은 ㄱ에 한 획을 더한 것", "ㅏ는 ㅣ에 ·". 한글 교육·한글날에 쓴다.
- **획 단위 변주**: 획 끝 흔들림, 획마다 다른 기울기. 자모 단위보다 손글씨답다. 겹침 감사가 폭을 정한다.
- **획 단위 교정**: 막대 두께와 내림획 길이를 따로 놓는다. 오늘 clip으로 푼 ㅜ·ㅗ 문제의 본래 해법이다.
- **키네틱 타이포**: 획이 흩어졌다 모인다(상호작용 `scatter`의 획 단위판).

### 6. 단계
1. ✅ 정본 `spec/strokes.json`(51자 획순·종류·부품)과 생성기(벡터 모듈 획순 표 + 칸마다 획 수 대조), ADR 확정
2. ✅ 런타임: 벡터 재료의 획 노드 출력, `stroke-depth` 옵션 해석(속성·JS·`--fy-stroke-depth`), hoek 레벨 변수, 단위·스모크 테스트, DOM 계약 문서([dom-contract.md](../../skills/font-kku/references/dom-contract.md) §3.4)
3. ✅ 움직임 `draw`(획순, 쪼갤 수 없는 재료는 자모 차례로), 변주 `kku-vary-hoek`(획 흔들림, 벡터 전용 — 겹침 감사는 jamo-set을 재지 않아 폭을 ±3°·칸 ±1.2%로 묶는다), 교육용 데모(움직임 페이지 '제자원리 보기', 문서 '획 깊이'), 조합 체계 축 값과 테마 `hoek-note`(글꼴 `jamoSet`이 있으면 조합법이 `jamo-set`을 단다)
4. 연구: 기기 글꼴 획 영역 사본

## Alternatives Considered
### 자모를 더 작은 자모로만 쪼갠다(ㅋ = ㄱ + ㅡ 같은 유니코드 자모 조합)
- 유니코드 자모에 '가획 한 획'은 없다. ㆍ(아래아)·ㅡ·ㅣ로 천지인은 표현되지만, 자음의 가획은 표현되지 않는다.

### 자모 노드를 늘리지 않고 CSS `nth-child`로 경로를 고른다
- 지금 벡터 자소로 이미 된다. 그러나 획 의미(종류·부품·획순)가 없어 자모마다 번호가 다르고, 글꼴마다 깨진다.

## Consequences
- 자모 아래 레벨이 생겨 변수 표면이 커진다. 레지스트리(`spec/css-variables.json`)와 계약 검사를 늘려야 한다.
- 기기 글꼴은 당분간 획 깊이를 받지 못한다. 획 깊이는 그림 자소·벡터 자소의 장점이 된다.
- 렌더 노드 수가 늘어난다(자모 1개 → 획 1–5개). 긴 글에서는 쓰지 않기를 권한다.
