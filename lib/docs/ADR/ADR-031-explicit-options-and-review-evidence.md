# ADR-031: 명시적 설정과 저장·검수 근거

## Status
Accepted (2026-10-18) — 사용자 "위 내용 바탕으로 개선 진행해줘"에 따라 구현했고, 아래 목록은 사용자 위임("네가 모두 판단해서 진행해줘")으로 브랜치 구현대로 정해 master 로컬 병합했다(`e92249e`). 처음 기록: 공개 API 의미·저장 형식 변경은 아래 목록을 보이고 master 병합 전에 확인한다.

## Context

글꼴의 디자인이 페이지 재료 설정을 덮고, 배치를 적지 않은 디자인이 기본 배치를 해제했다. 기본 세벌식을 명시적으로 고를 페이지 변수도 없었다. 파생 CSS의 원문 복사는 코어 모양 값과 그림 자산까지 고정하지 않는다. 검수 결과를 고친 글꼴의 특정 상태에 연결하는 저장 경로도 필요하다.

## Decision

### 설정

- 배치 선택은 페이지 디자인의 layout → 페이지 `--fy-layout` → 글꼴 디자인의 layout → 글꼴 `--fy-font-layout` → 글꼴을 생략했을 때의 기본 세벌식 차례다. 생략한 디자인 layout은 다음 출처를 물려받는다.
- `--fy-layout`은 `sebul-cases-v1`(기본 세벌식), `sebul-fixed-v1`(직결식), `square-context-v1`(글꼴 CSS의 문맥 자리)을 받는다. 글꼴 생략과 명시적 `font="sebul"`의 기존 차이는 호환상 유지하고, 새 코드는 원하는 모양을 명시할 수 있다.
- 같은 레벨에서는 디자인이 재료를 정한다. 페이지 재료·그림 세트 지정은 글꼴 레벨 디자인의 재료·조립 적용보다 우선한다. 독립적으로 해석한 배치는 유지한다. `DESIGN_OVERRIDDEN_BY_PAGE`로 이유를 알린다.
- `--fy-design: legacy`는 디자인만 끈다. 예전 문맥 배치까지 선택하려면 `--fy-layout: square-context-v1`을 함께 쓴다.
- 그림 세트가 없는 `--fy-face: svg`는 원소 재료로 그리고 `SVG_REQUIRES_BOX_SET`을 남긴다. 배치 이름 오류는 `LAYOUT_NOT_REGISTERED`, 해당 글꼴이 받을 수 없는 배치·재료는 `LAYOUT_UNSUPPORTED_FONT`·`FACE_UNSUPPORTED_FONT`로 알린다. 잘못된 재료 값은 `FACE_TOKEN_INVALID`로 알리고 하위의 유효한 설정을 유지한다.

### 저장

- 파생 CSS가 고정하는 것은 복사한 바탕 CSS 원문이다. 런타임·코어 CSS의 모양 값·외부 그림·기기 글꼴까지 고정한다는 뜻은 아니다. 통째로 풀기는 표시 제거이며 의존성 굽기가 아니다.
- 프로젝트·디자인 묶음의 선택적 `reproducibility`는 런타임 판, 배치 revision, 자원 식별자와 내용 지문을 담는다. 원문 실행·임의 주소 요청은 이 모델의 책임이 아니다.
- 비교 결과는 일치·변경·미확인이다. 같은 이름/판이라도 내용이 다르면 변경으로, 지문이 없는 외부 자원은 미확인으로 남긴다. 일치는 확인한 의존성의 일치이며 화면 화소 동일성을 보장하지 않는다.
- 저장한 환경은 읽기·저장만으로 갱신하지 않는다. 사용자가 현재 환경으로 갱신할 때만 바꾼다. 옛 프로젝트에 근거가 없으면 미확인으로 열어 계속 편집한다.

### 검수

- 작업실 네 번째 페이지 `review`에서 실제 글자를 크기별로 보고 판정·메모를 저장한다. 선택한 문장을 고치기 페이지로 보내고 돌아올 수 있다.
- 판정은 CSS·디자인·재료·실행 환경의 지문에 연결한다. 변경 뒤 이전 판정을 지우지 않고 다시 검수할 항목으로 표시한다. 현재는 보수적으로 프로젝트 전체를 재검수 대상으로 삼는다.
- 검수 기록과 이전 상태 비교는 프로젝트·초안의 일부다. 비교 기준은 CSS·디자인·담긴 재료를 한 번 복사하며 현재 실행 환경에서 두 결과를 그린다. 예전 런타임이나 당시 화면을 보관한다는 뜻은 아니다. 원본 없는 외부 재료는 비교할 수 없는 이유를 표시한다. LLM 호출은 요구하지 않는다.

### 공통 판단과 지원 명세

- 조립 규칙 선택은 순수 모듈 `authoring/font-kku-rule-resolution.js` 한 곳에 둔다. 런타임에는 그 본문을 생성하고 작업실 설명은 같은 모듈을 직접 사용한다. 배포 런타임의 한 파일 설치는 유지한다.
- `spec/capabilities.json`의 `htmlOptions`에 나누기·재료 지원을 구조화한다. 네 언어 시험이 그 지원 조합을 실제로 그린다. 지원은 그릴 수 있다는 뜻이며 모든 글꼴·크기의 시각 교정 완료를 뜻하지 않는다.

## Compatibility and Approval

master 병합 전에 확인할 변경:
1. 페이지 재료가 글꼴 디자인을 이김, layout 생략의 상속, `legacy`의 배치 해제 제거.
2. 새 페이지 변수 `--fy-layout`, 새 진단과 그림 없는 svg의 원소 대체.
3. 프로젝트·묶음의 선택적 저장 환경 및 검수 필드, 검수 페이지·mount 옵션 추가.

새 설정을 쓰지 않는 기본 글꼴의 좌표·revision은 바꾸지 않는다. 기존 데이터는 받아들이며 위 의미 변경은 CHANGELOG와 사용법에 명시한다. 기준선·감사 문턱을 완화하지 않는다.

### 2026-10-18 검수 지문 바꿈 (PLAN-STUDIO-002 S0, 사용자 결정 ⚑8 기본값)
- 지문은 글꼴 내용(CSS·디자인·자소판·그림)과 런타임·의존성이다. UA·화면 배율·세션은 참고로만 남긴다 — 기기를 바꾸거나 다시 열어도 판정이 그대로다.
- 다시 검수는 항목마다 정한다. 판정 때 적은 그 항목의 그린 모양 서명과 지금을 견준다(위 '검수'의 "프로젝트 전체를 재검수"를 대신한다).
- 판정 어휘는 `pass`·`needs-fix`·`hold`(통과·고칠 것·보류). 기록 판 2가 판 1을 읽어 바꾼다.

## Limits

- 저장 환경 기록은 옛 런타임 파일을 보관·설치하는 기능이 아니다. 옛 모습이 필요하면 해당 패키지 판과 외부 자원을 함께 보관해야 한다.
- 정적 원소 표 생성기의 런타임 함수 추출은 유지한다. 이번 공통화는 그리는 쪽과 설명하는 쪽의 규칙 선택에 한정한다.
- 검수의 변경 영향 범위는 현재 프로젝트 전체다. 자모별 영향 추적과 저장소 교정 파일 적용 도구는 후속이다.
